ヤマト運輸 MCP 利用ガイド

Claude のチャットから、ヤマト運輸の荷物追跡（配達状況・履歴・注文番号からの逆引き・1日分の一括チェック）、送料（請求データ）の照会、スマートキャットの発行済み送り状と取込エラーの照会、そして送り状の発行（B2クラウド API・2026年10月1日から本番）ができる社内コネクタです。照会はすべて無料ですが、送り状の発行は 1 件ごとに料金がかかります。

💴 送り状の発行は 1 件 20 円（税抜）の API 利用料がかかります。
宅急便の運賃とは別に、ヤマトから月ごとに請求されます。発行した伝票は取り消せません（使わなかった分も 20 円は発生します）。 通常の出荷は今までどおり GoQ／スマートキャットで行い、Claude からの発行は返品交換の再送・例外出荷など少量の場合だけに使ってください。 様子見の期間として 全員合わせて 1 日 50 件までに制限しており、超えると発行が止まって Chatwork に通知が飛びます。

注意事項

  • 利用は Claude デスクトップアプリの「Code」タブで行ってください。ブラウザ版の通常チャットではなく、Code の画面で質問・操作します
  • これは正規のヤマト運輸コネクタではありません。生成AIで作成した電池屋用のコネクタです。不具合が入っている可能性があります。おかしな動きに気づいたら、そのまま使い続けずに市倉さんへ
  • 発行（issue_label）は必ず確認画面が先に出ます。「confirm: true」で実行するまで伝票は発行されません。確認画面の内容（お届け先・品名・種類）を必ず読んでから進めてください
  • PDF のダウンロード URL は 10 分間だけ有効です。開いてすぐ保存・印刷してください。逃した場合は B2クラウドの画面「発行済み」から印刷できます
  • お届け先の氏名・住所は個人情報です。追跡結果を Chatwork などに貼るときは伝票番号と状態だけにしてください

はじめる（初回だけ・3分）

  1. 招待コードを手に入れる。Chatwork で コダック（RPA用アカウント）とのダイレクトチャットを開き、To を付けて「招待コードをください」と送ると、数秒で自分専用のコードが返ってきます
  2. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-ヤマトMCP をオンにする
  3. 初めて使うときに認可画面が開くので、招待コードを貼り付けて「接続を許可する」を押す。以後1年間はコードの入力は不要です。1年ごとに繋ぎ直しが要りますが、切れる前（14日前と3日前）にコダックからDMでお知らせが届きます（繋ぎ直す手順と招待コード付き）
  4. 作業は Claude デスクトップアプリの「Code」タブで行います。アプリを開き、上部の Code を選んで新しいセッションを始めてください。コネクタは設定で一度オンにすれば Code 側でも使えます
このコネクタは 全員（管理者・ウェブチーム・一般） が使えます。送り状の発行も全員ができますが、1 件 20 円の有料で取り消せない操作です。発行前の確認画面を必ず読み、使うのは返品交換の再送・例外出荷など少量の場合だけにしてください。役割に含まれない人は「このコネクタの利用権限がありません」と表示されます。

送料とスマートキャットのデータ（社内に取り込んだ写し）

追跡と発行はヤマトに直接つながりますが、送料とスマートキャットの3本は、社内サーバに届いたファイルを取り込んだ写しを読みます。性質が違うので先にここを読んでください。

データどこから・いつ中身と注意
送料（請求データ）クラウドB2の請求データを RPA が落としたもの。締め期間の累積で、受付から数日〜締めまで遅れて載る送り状番号ごとの運賃・立替金・保険料・サイズ・商品区分・請求先お客様コード。金額は税別。注文番号で聞くとエアロジの出荷実績から送り状番号を引いて突き合わせます。締め前の最新分は載っていないことがあるので、回答には必ずデータの範囲が付きます
スマートキャットの紐データ
発行済み送り状		山梨倉庫の出荷検品・送り状発行（スマートキャット）が出す紐データを、山梨のスタッフが FTP に上げたもの。2024年5月以降の分を取り込み注文番号・送り状番号・送り状種別・出荷予定日・請求先コード・お届け先の都道府県だけ（氏名・住所・電話は取り込んでいません）。上げる前に消されることもあるので「載っていない＝発行していない」ではありません。エアロジの出荷実績より早く（発行した時点で）載ります
スマートキャットの取込エラー同じく山梨のスタッフが上げるエラーファイル。2024年7月以降の分を取り込み注文番号・項目・内容・種類（郵便番号と住所の不一致／郵便番号の不備／文字数超過／荷受停止地域／重複／その他）。住所や氏名の断片（「入力値：…」）は取り込んでいません。「重複」（同じ出荷指示番号が存在します）はふだん無視してよいので一覧では外していますが、発行後に受注を直して同じ番号で登録し直したときも「重複」で止まるため、注文番号で調べたときは必ず表示します
💡 モール別・都道府県別の分析もできます（住所を間違えやすいモールは？）。モールは注文番号の形で判定します。都道府県は、そのエラーの注文が後で発行されたときの紐データから引くので、まだ発行されていない注文は「不明」になります。スマートキャットは山梨倉庫だけです（柏センコーの出荷は含まれません）。

拠点（契約）の選び方

ヤマトとの契約は 山梨・東京本社・茨城支店 の 3 つあり、MCP では account で切り替えます。荷物を実際に集荷してもらう拠点の契約を選んでください。ご依頼主の印字はどの契約でも本社（株式会社電池屋・渋谷区笹塚）で共通です。

account契約使いどころ
yamanashi山梨山梨倉庫から出す荷物。迷ったらこれ
tokyo東京本社本社から出す荷物（サンプル・書類・例外対応）
ibaraki茨城支店柏センコー（常総市）から出す荷物
発行では account の指定が必須です（運賃の請求先が変わるため）。追跡では省略でき、配達状況はどの契約で聞いても同じ結果です。条件検索（電話番号・名前などから探す）は出した契約でしか見つからないため、拠点を言わなければ 3 契約を順に探します。お届け先情報付きの追跡も、空なら他の契約に自動で問い合わせます。追跡では拠点を意識する必要はありません。

送り状発行の流れ

  1. 拠点・お届け先・品名・注文番号を伝える。拠点（山梨／本社／柏）は必ず伝えてください。言わなければ Claude が聞き返します（運賃の請求先と集荷場所が変わるため、推測はしません）。ご依頼主と請求先コードは拠点の既定値が入るので言わなくてよい。宅急便コンパクト・ネコポス・コレクトなどは種類を指定
  2. Claude が B2クラウドの入力チェックにかけて確認画面を出す。住所の不備や必須項目の不足はここで分かる。確認画面には「ご依頼主」（送り主として印字される情報）が必ず出ます。既定は本社（株式会社電池屋・渋谷区笹塚）なので、それでよいか毎回確認してください。変えるときは「ご依頼主は山梨倉庫の住所で」のように伝える。この時点では発行されておらず、料金もかからない
  3. 内容を確認して「発行して」と伝える。ここで 20 円が発生し、伝票番号が確定する。取り消しはできない
  4. PDF の URL を開いて印刷する（10 分以内）。既定は A5 マルチです（A4 がよければ「A4 で」と伝える。ネコポス・ゆうメールは種類に合う形式を自動で選びます）。ファイル名は 日付時刻_yamato_送り状番号.pdf。応答には伝票番号も載るので、そのまま追跡に使える
⚠️ 同じ注文への二重発行は自動で止まります。同じ注文番号（お客様管理番号）で 30 日以内に API から発行済みなら、発行歴を表示して止まります。本当にもう1枚必要なとき（複数口の追加など）だけ「もう1枚必要」と伝えてください。スマートキャットや B2 画面で発行した分は対象外なので、そちらで出した注文は 注文 ○○ はスマートキャットで発行済み？ と先に確認を。
発行した送り状は、B2クラウドの画面で 検索キー1「発行元 = ClaudeMCP」・検索キー2「発行者 = 社員ID」 が付くので、スマートキャットや画面から出したものと見分けられます（送り状には印字されません）。

料金と請求先

  • API 利用料：1 件 20 円（税抜）。送り状番号が出た時点で発生し、使わなくても戻りません。毎月 20 日締め・翌月 26 日に口座引落。宅急便の運賃とは別の請求（お客様コード 033378015603・WEB請求書提供サービスで通知が届きます）
  • 運賃：発行時に選んだ拠点の契約（山梨／東京本社／茨城支店）に、いつもの宅急便の請求として付きます
  • 突合：今月 API で発行した件数と利用料の概算は？ で、月ごと・拠点ごと・発行者ごとの件数が出ます（前月 21 日〜当月 20 日で区切ると請求書と合わせやすい）

まだできないこと（ヤマト側の制約）

機能使えない理由
荷物追跡の速さヤマトの規約で「1 回 20 件まで・前の応答から 5 秒あける」と決まっています。1 日分 2,000 件で約 10 分かかるのはこのためです
追跡の履歴の件数作業履歴は最新 5 件まで。それより前の経路は返りません
紐データ・エラーの網羅性スマートキャットのファイルは山梨のスタッフが手で FTP に上げるため、上げる前に消えた分は載りません。「載っていない」は「発行していない」の証拠にはなりません

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「発行されているかどうか」まで書いてあります。「送信したあとの失敗です」と出たときだけ、再実行せずに B2クラウドの画面で発行状況を確認してください（再実行すると二重発行になります）
  • 「1 日の発行上限に達しました」と出たら、その日は API からの発行はできません。急ぐ分は B2クラウドの画面で発行し、上限の見直しは市倉さんへ
  • 「ヤマトに未登録」が続く伝票は、集荷がまだの可能性があります。翌日にもう一度
  • 「二重発行の疑い」で止まったら、表示された発行歴を見て、本当にもう1枚要るときだけ「もう1枚必要」と伝えてください
  • 急に「再接続してください」「connection was invalidated」と出たら、コネクタの1年の期限切れです。コダックに「期限」と送ると自分の期限が分かります。設定 → コネクタで一度切断し、接続し直して招待コードを入れてください
  • 招待コードはコダックへ To 付きで「招待コードをください」（期限切れも同じ）。「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ
