NetSuite MCP 利用ガイド

Claude のチャットから NetSuite（オラクル） の受注・請求・発注・入荷・在庫・品目・取引先を調べられる社内コネクタです。あなた自身の NetSuite アクセストークンで動くので、見える範囲は NetSuite であなたのロールに見えるものと同じです。純正の NetSuite コネクタと違い、7日ごとに切れることはありません。

注意事項

  • 利用は Claude デスクトップアプリの「Code」タブで行ってください。ブラウザ版の通常チャットではなく、Code の画面で質問・操作します
  • これは正規の NetSuite コネクタではありません。生成AIで作成した電池屋用のコネクタです。不具合が入っている可能性があります。数字がおかしいと感じたら NetSuite の画面で確かめてください
  • 見える範囲・できることは、あなたの NetSuite のロールと同じです。Claude 経由で見えないものは、画面でも見えないものです
  • 変更できるのはメモ・外部ID・カスタム項目と、取引の納期（出荷日）・期日・発注書/小切手番号・営業担当・配送方法です。金額・数量・ステータス・明細・取引先は変更できません。変更は必ず確認画面が先に出て、NetSuite の変更履歴にはあなたの名前で残ります
  • トークンはあなたの社員IDにだけ紐づけて暗号化して保存されます。他の人には見えません。トークンを他人に教えないでください（あなたとして NetSuite を操作できる鍵です）
  • NetSuite の在庫は基幹の帳簿在庫です。倉庫の実在庫（エアロジ）と違うことがあります。倉庫の数字はエアロジ MCP で

はじめる（初回だけ・5分）

  1. 招待コードを手に入れる。Chatwork で コダック（RPA用アカウント）とのダイレクトチャットを開き、To を付けて「招待コードをください」と送ると、数秒で自分専用のコード（INV-あなたの名前-…）が返ってきます。全コネクタ共通・30日有効。すでに持っていればこの手順は不要です
  2. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-NetSuiteMCP をオンにする
  3. 初めて使うときに認可画面が開くので、招待コードを貼り付けて「接続を許可する」を押す。以後、コードの入力は二度と不要です。
    ⚠️ コネクタをつないだだけでは NetSuite は読めません。4〜5の手続きをしてください。
  4. 作業は Claude デスクトップアプリの「Code」タブで行います。アプリを開き、上部の Code を選んで新しいセッションを始めてください。コネクタは設定で一度オンにすれば Code 側でもそのまま使えます（以後の手順・質問はすべて Code の画面で）
  5. NetSuite で自分のアクセストークンを発行する：「新しいマイアクセストークン」。アプリケーション名「電池屋 Claude MCP」、ロールは普段のもの、トークン名は自動で入る名前のまま → 保存。
    ⚠️ ここが重要：保存後の画面の下部「トークンID/シークレット」に2つの値が出ます。この画面を閉じると二度と表示されません。閉じる前に、次の手順5で Claude に登録してください（控え忘れたら作り直し）。
  6. 4で発行した「トークンID/シークレット」を Claude に渡してください。Claude に NetSuite の MCP でトークンIDは ◯◯◯、シークレットは ◯◯◯ です と伝えてください。「登録しました」と返れば完了です。
    ⚠️ この作業をしないと使えません。

トークンをなくしたら、同じトークンのページで古いものを取り消し、「新しいマイアクセストークン」で作り直してもう一度登録してください。

このコネクタは 全員（管理者・ウェブチーム・一般） が使えます。役割に含まれない人は、正しい招待コードを入れても「このコネクタの利用権限がありません」と表示されます。自分の役割が分からないとき・権限の相談は市倉さんへ。

できないこと

やりたいことできる？理由・代わりの方法
受注・請求書などの新規作成✕作っていません。必須項目の推測や二重登録の事故を避けるため。作成は NetSuite の画面か RPA で
金額・数量・ステータスの変更✕影響が大きいため対象外。変更できるのはメモ・外部ID・カスタム項目だけ
保存検索の結果を編集・保存する✕保存検索は「実行して結果を見る」だけです。条件や列の変更は NetSuite の画面で
自分のロールで見えないデータ✕NetSuite 側で権限エラーになります（本人の権限と同じ）
倉庫の実在庫・棚番✕NetSuite は帳簿在庫です。倉庫の実数・ロケーションはエアロジ MCP で
大量の全件取得△1回 1,000 行まで。続きがあるときは Claude が「まだ続きがある」と伝え、必要なら次ページを取ります
作れるが、意図して作っていない操作（要望があれば項目単位で追加を検討）
受注・発注・顧客の新規作成✕必須項目の推測ミスと二重登録が実害になるため。GoQ・RPA の流れとも競合する。作るなら影響の小さい「見積書の作成」が候補
数量・金額・ステータスの変更、受注のクローズ✕在庫・売上に直結し、復旧が難しい。作らない方針
出荷（Item Fulfillment）の作成✕エアロジ→RPA の流れがあり、二重化するため作らない
上記以外の項目の更新（取引先・ロケーション・支払条件など）△納期・期日・発注書番号・営業担当・配送方法は 2026-09-08 に開放済み。他の項目は業務ルールを決めて、項目を1つずつ指名して許可リストに足す形で対応できる（市倉さんへ）
ノート（コミュニケーション履歴）の追加△取引本体を変えずに記録できる安全側の書き込み。需要があれば追加できる
レポート（財務レポート等）の実行✕REST にも SuiteScript にも無い機能。NetSuite の画面で
2026年9月7日に作った新しいコネクタです。照会26本と、メモ・社内コメントの更新（往復）を実データで動作確認済みです。おかしな結果が出たら市倉さんへ。

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「次に何をすればいいか」まで書いてあります
  • 「トークンが無効」と出たら、NetSuite でトークンが取り消されたか、コピー漏れです。トークンのページ で古いものを取り消し、「新しいマイアクセストークン」で作り直して register_token で登録し直してください
  • 「権限がありません」は、あなたのロールにその操作の権限が無い状態です。市倉さんに相談してください
  • 招待コードはコダックへ To 付きで「招待コードをください」（期限切れも同じ）。「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ
