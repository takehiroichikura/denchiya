楽天MCP 利用ガイド

Claude のチャットから、楽天市場（RMS）の受注・問い合わせ・商品・在庫を調べたり、操作したりできる社内コネクタです。2026-09-18 から、楽天の精算書（BillPay）も引けるようになりました——入金の内訳、楽天へ払った費用、注文1件ごとの入金額まで。使い方はぜんぶ「日本語で聞くだけ」。このガイドは最初の接続と、安全に使うための約束ごとをまとめたものです。

注意事項

  • 利用は Claude デスクトップアプリの「Code」タブで行ってください。ブラウザ版の通常チャットではなく、Code の画面で質問・操作します
  • これは正規の楽天コネクタではありません。生成AIで作成した電池屋用のコネクタです。正規のコネクタではないので、不具合が入っている可能性があります。おかしな動きに気づいたら、そのまま使い続けずに市倉さんへ知らせてください
  • このコネクタは RMSの操作がほぼひととおりできます。便利な分、間違えたときの影響も大きいので、変更する操作は最大限気を付けてください。プレビューの確認を省略しないこと
  • 楽天市場のお客様情報（氏名・住所など）を扱います。回答や画面の内容を社外へ共有しないでください。チャットに顧客情報を不必要に貼り付けるのも控えてください

はじめる（初回だけ・3分）

  1. 招待コードを手に入れる。Chatwork で コダック（RPA用アカウント）とのダイレクトチャットを開き、To を付けて「招待コードをください」と送ると、数秒で自分専用のコード（INV-あなたの名前-…）が返ってきます。全コネクタ共通・30日有効。すでに持っていればこの手順は不要です
  2. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-楽天MCP をオンにする
  3. 初めて使うときに認可画面が開くので、招待コードを貼り付けて「接続を許可する」を押す。以後、コードの入力は二度と不要です
  4. 作業は Claude デスクトップアプリの「Code」タブで行います。アプリを開き、上部の Code を選んで新しいセッションを始めてください。コネクタは設定で一度オンにすれば Code 側でもそのまま使えます（以後の手順・質問はすべて Code の画面で）
このコネクタを使えるのは 管理者・ウェブチーム です。役割に含まれない人は、正しい招待コードを入れても「このコネクタの利用権限がありません」と表示されます。自分の役割が分からないとき・権限の相談は市倉さんへ。

精算書のデータ（2026-09-18 追加）

精算の4本だけは、RMSのAPIではなく楽天から届いた精算書のファイルを社内に取り込んだものを読みます。ほかの道具と性質が違うので、先にここを読んでください。

項目中身
どこから来るか楽天が月2回（5日ごろ・20日ごろ）出す精算パッケージ（ZIP）。RPAがダウンロードしたものを、加工せずそのまま社内DBに取り込んでいます
いつ見えるか精算書が発行されてから。締めの直後の売上はまだ載りません。「今日の入金」のような使い方はできません
5日発行の回入金だけ（楽天→電池屋）。対象期間は直前の2週間で、ラグはほぼありません
20日発行の回入金＋請求（電池屋→楽天の費用）。請求の中身は2〜3か月前の営業分です
「8月の請求書」と「8月分の費用」は別物です。 8月20日発行の請求書に載っていたのは、システム利用料・ポイント付与料・アフィリエイト・RPP広告が5月分、楽天ペイ利用料とスーパーロジスティクスが6月分、チャージバック補償保険が7月分でした。 品目ごとにラグが違うので、「5月分のシステム利用料」（対象月で言う）か「8月20日締めの請求内訳」（発行日で言う）のどちらかで聞くと迷いません。答えには必ず「精算対象期間」が付きます。

知っておくと役に立つこと

こと内容
精算額は引き算 入金（支払）と費用（請求）は向きが逆です。精算額＝入金計−費用で、楽天の資料の「ご精算額」と同じ計算になるよう揃えてあります。金額の符号は資料のまま残しているので、控除は負（請求書で −8,000）、同じものが明細では正（8,000）で出ます
楽天ポイントの行も入る 1注文でポイント併用なら、入金明細は2行（ポイント分とカード分）になります。RPAが作る加工済みCSVではポイント行が落ちていたので、そちらと数字が合いません。こちらが楽天の原本どおりです
明細が無い品目がある 費目の金額はすべて引けますが、1件ずつの明細まで追えるのはシステム利用料・ポイント付与料・楽天ペイ利用料・アフィリエイト・スーパーロジスティクスだけです。RPP広告掲載料・compass・snapp・保険料などは金額だけで、内訳は付いてきません（広告費の内訳はRMSの広告レポートを見てください）
PC／モバイル別の売上 デバイス別の売上が分かるのはこのデータだけです（システム利用料の課税対象額がPCとモバイルで別ファイルになっているため）。ただし受注日ベースなので、NetSuiteの請求書日付ベースの売上とは月初月末でずれます
「取り込み範囲」が必ず付く 答えの最後に、入っている精算書の本数と発行日の範囲が出ます。「回数が2回未満の月」が並んでいたら、その月は取り込みが済んでいないか、実際に1回だけだったかのどちらかです。そのまま合計を信じないでください
「◯月分」で聞くのが確実 同じ対象月の費用が2枚の精算書に散ることがあります（2026年5月分は、システム利用料とポイント付与料が8月20日発行、楽天ペイ利用料が7月17日発行）。「5月分の費用」と対象月で聞けばまとめて拾えます。発行日で聞くと片方しか出ません
NetSuiteと突き合わせるとき。受注番号（244970-…）はNetSuiteの注文番号と同じ形式なので、そのまま行き来できます。ただし期間の基準が違います——精算書は受注日または決済確定日、NetSuiteは請求書日付・出荷日。月次で比べるなら基準をどれか1つに決めてください。

まだできないこと（楽天側の制約）

楽天が提供している機能のうち、電池屋が契約していてまだ道具にしていないものは十数件まで減りました（2026-09-02）。 残りは「危ないので個別に判断する」ものと「使う場面が無い」ものです。

変更する操作（書き込み）の約束ごと

AIがプレビューを出す→自分の目で確認→OKなら実行を指示

価格変更・返信送信などの「変更する操作」は、いきなり実行されることはありません。AIが必ず変更内容のプレビュー（宛先・金額・変更前→変更後）を見せてくるので、内容を確認してから実行を伝えてください。

  • 実行した記録（誰が・いつ・何を）はすべて残ります
  • ほとんどの変更は、プレビューに表示される「変更前」の値を使って元に戻せます。大事な変更のときは控えておくと安心です
  • 実行後は「反映確認」まで見てください（2026年8月30日から）。実行するとRMSから読み直して、期待どおりの値になっているかを突き合わせます。OK（再取得で反映を確認）なら反映済み、⚠️ 期待値と違いますならまだ反映されていないか、GoQやRPAと競合しています。この場合はRMS画面で確認してください
  • 問い合わせのまとめて完了化・既読化は、プレビューで1件ずつの現在の状態を出し、すでにその状態のものは「変更不要」として分けて表示します。状態の確認は先頭20件までなので、心配なときは20件以下に分けて指示してください
⚠ 「問い合わせへの返信送信」と「キャンセル申請」だけは取り消せません。お客様に直接届く操作です。プレビューを必ず読み合わせてから実行してください。
変更系のツールは、会社の方針で最初は「ブロック」になっている場合があります。業務で必要なときは、コネクタ設定の「ツールの権限」で該当ツールを有効にしてください（判断に迷ったら市倉さんへ）。

アーティファクトから楽天を使う

Claudeが作る「アーティファクト」（共有できる画面）から、このコネクタを呼べます。 楽天は社内の機器を経由しないので、Yahooのような時間帯・順番待ちの制約はありません。ただし共通の注意が2つあります。

  • 「確認してから実行」が効かなくなります。 チャットではAIがプレビューを出して人が判断しますが、画面の中では作った人が書いたとおりに実行されます。しかも記録は開いた人の操作として残ります。
    → 画面に組み込むのは読み取りだけにしてください。 変更する操作を入れたい場合は先に市倉さんへ
  • 社外に共有できません。 コネクタを使う画面は社内配布のみです

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「次に何をすればいいか」まで書いてあります（番号の確認・管理者への依頼・RMS画面からの復旧など）
  • 招待コードはコダックへ To 付きで「招待コードをください」（期限切れも同じ）。権限の相談、「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ。要望は「どの業務で・何を知りたい／したいか」を添えてもらえると早く作れます
