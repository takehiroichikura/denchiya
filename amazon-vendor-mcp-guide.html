Amazonベンダー MCP 利用ガイド

Claude のチャットから、Amazonベンダーセントラル（Amazonへの卸取引）のデータ——発注書(PO)・出荷売上・閲覧数・Amazon側の在庫——を調べられる社内コネクタです。電池屋・電池屋 BISS/M・誠和商工 HPC/R の3アカウントに対応しています。

注意事項

  • これは正規のAmazonコネクタではありません。生成AIで作成した電池屋用のコネクタです。正規のコネクタではないので、不具合が入っている可能性があります。おかしな動きに気づいたら、そのまま使い続けずに市倉さんへ知らせてください
  • 卸取引のデータ（発注・原価・売上）を扱います。回答や画面の内容を社外へ共有しないでください
  • アカウントが3つあります（電池屋／電池屋 BISS/M／誠和商工 HPC/R）。AIがどのアカウントの数字かを必ず添えて答えますが、読むときも「どの会社の話か」を確認してください

はじめる（初回だけ・3分）

  1. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-AmazonVendorCentralMCP をオンにする
  2. 初めて使うときに認可画面が開くので、招待コード（INV-あなたの名前-…）を入力する。他のMCPコネクタと同じコードです
  3. 「接続を許可する」を押して完了。以後、コードの入力は二度と不要です

招待コードの有効期限は発行から30日（約1か月）です。期限切れ・紛失のときは市倉さんに再発行を依頼してください。

できること（聞き方の例）

分野こんなふうに聞く
発注（PO） 電池屋あてのAmazonの発注書、今週の分を見せて／PO番号◯◯の明細は？／未確認の発注はある？
小売分析 先週のAmazonでの出荷売上の推移は？／昨日のAmazon側の販売可能在庫は？（在庫は1日指定で）／ブランド別の売れ行きを見せて／ASIN別の閲覧数と売上は？
カタログ JAN◯◯の商品をAmazonで探して／このASINの商品情報は？
レポート・取引 ◯◯のレポートを出して／この取引ID、Amazonに受理された？
💡 セラー（自社出品・マーケットプレイス販売）のデータは別のコネクタ「Amazonセラー MCP」です。「電池屋のAmazonの数字」と聞くとAIがどちらか確認するので、「ベンダーの」「セラーの」を付けると速いです。

できないこと

  • 直送（DF）関連 — Amazonの追加審査が必要なため未対応です
  • 出荷通知(ASN)の照会 — 準備中です（権限の追加待ち）
  • 発注への回答・出荷通知の送信 — UiPath（RPA）の担当領域です

請求書の提出（管理者向け）

このコネクタで唯一の「変更する操作」として、Amazonへの請求書(インボイス)提出があります。通常業務で使うことはありません。誤って提出した場合の取り消しはAmazonサポート経由になるため、経理・管理者以外は触らないでください。

安全側に倒すため、次の3つが必ず働きます（2026年8月30日に強化）。

  • 2段階の確認 — 1回目の呼び出しでは提出せず、送信する内容の全体（送金先・明細・金額）と確認コードを表示します。内容を確認したうえで、その確認コードを付けて2回目を実行したときだけ提出されます。確認後に金額や明細を変えると確認コードが合わなくなり、提出されません（見せた内容と違う請求が立つのを防ぐため）
  • 二重提出の防止 — 提出済みの請求番号は記録されており、同じ番号をもう一度提出しようとすると止まります。本当に再提出が必要な場合だけ、AIに「重複を承知で再提出する」と明示的に伝えてください
  • 提出前の内容チェック — 送金先が空、明細が空、金額の形が違う、明細の合計と請求総額が合わない、といった不備はAmazonへ送る前に止めて理由を表示します
⚠️ 送信の途中で通信エラーになった場合は「提出されたか分からない」と表示されます。このときは再提出せず、取引IDの照会かVendor Centralで受理状況を確認してください（確認せずに再提出すると二重請求になります）。

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「次に何をすればいいか」まで書いてあります
  • 招待コードの再発行、「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ
