Amazonセラー MCP 利用ガイド

Claude のチャットから、Amazonセラーセントラルのデータ（注文・FBA在庫・自社出品・価格・手数料・売上・入金）を調べられる社内コネクタです。ふだんの使い方は照会です。変更する操作（6本）は管理者向けで、確認画面を経てからしか実行されません。

注意事項

  • これは正規のAmazonコネクタではありません。生成AIで作成した電池屋用のコネクタです。正規のコネクタではないので、不具合が入っている可能性があります。おかしな動きに気づいたら、そのまま使い続けずに市倉さんへ知らせてください
  • 取引データ（注文・価格・売上）を扱います。回答や画面の内容を社外へ共有しないでください

はじめる（初回だけ・3分）

  1. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-AmazonSellerCentralMCP をオンにする
  2. 初めて使うときに認可画面が開くので、招待コード（INV-あなたの名前-…）を入力する。楽天MCP・UiPath MCPと同じコードです
  3. 「接続を許可する」を押して完了。以後、コードの入力は二度と不要です

招待コードの有効期限は発行から30日（約1か月）です。期限切れ・紛失のときは市倉さんに再発行を依頼してください。

できること（聞き方の例）

分野こんなふうに聞く

在庫（FBA） FBAの在庫一覧を見せて／SKU◯◯のFBA在庫は？

入金・手数料 直近の入金サイクル（決済期間）と入金額を一覧にして／注文◯◯の手数料の内訳は？／先月の取引明細を出して
FBA納品・MCF 進行中のFBA納品プランは？／納品◯◯の受領状況を見せて／マルチチャネル（MCF）の注文と追跡番号は？

レビュー・販促 ASIN◯◯のレビューでよく出る話題は？／今走っているクーポン・セールの一覧は？／注文◯◯にレビュー依頼は送れる？
カタログ・レポート JAN◯◯の商品をAmazonで探して／全出品のレポートを出して
💡 よくある誤解に注意：このコネクタの「在庫」はFBA（Amazon倉庫）在庫だけです。0と表示されても自社出荷（FBM）の在庫は別にあります——実在庫の全体はNetSuiteで確認してください。また、カタログ検索で出てくる価格は市場の参考価格で、自社の販売価格は「自社出品」の聞き方で確認します。
⚠️ 件数や合計を聞くときの注意（2026年8月30日に改善）。アクセス分析はSKUが数百〜数千件になるため（実測で1,623件）、1回の取得では一部しか返りません。以前は「200件だけ返っているのに全件のように見える」状態でしたが、いまはこれは全量ではありませんと表示され、AIが続きを取りに行けるようになっています。「◯件あった」「合計は◯円」という答えが返ってきたら、全部見た結果かどうかを一度確認してください。表示に「全量ではありません」と出ているうちは途中です。

ツール一覧（53本）

AIが裏で使っている道具の一覧です。「これは頼めるのか」を確かめたいときに見てください。書＝変更する操作（6本）。変更する操作はすべて確認画面が先に出て、確認コードを付けた2回目でだけ実行されます（2026年9月2日に追加。それまでは照会専用でした）。

できないこと

  • 購入者の氏名・住所を見る — 個人情報のため Amazon の追加審査（制限ロール）が必要で、申請していません。配送先は GoQ / NetSuite で確認してください
  • お客様にメッセージを書いて送る — 送れる種別の確認まで。文面を作って送る操作は用意していません（送れるのは Amazon 固定文の「レビューのお願い」だけ）
  • 出品の削除・まるごと置き換え、FBA納品プランの作成、MCF注文の作成 — 事故の幅が大きい／手順が多いのでセラーセントラルの画面で行ってください
  • ベンダー（Vendor Central）のデータ — 別のコネクタ「Amazonベンダー MCP」です

まだできないこと（Amazon側の制約）

SP-API（Amazonの公開仕様）にある操作のうち、電池屋のコネクタで使えないものです。

機能使えない理由
入金・手数料、フィード、FBA納品、MCF、AWD、メッセージ種別の照会API権限が現状なく使えません（2026年9月2日実測で権限エラー）。接続の作り直し（所有者による再認可）で直る見込み。直ったらこの行を消します
購入者の氏名・住所・電話番号API権限が現状なく（制限ロール「購入者情報」未申請）、取れません
通知の送信先（destinations）の一覧・作成アプリ単位の別トークンが必要で、このコネクタの認証経路では取れません
レビューの話題分析（ブランド分析）ブランド登録のあるASINだけが対象の可能性。対象外なら権限エラーになります
入金・手数料の長期間まとめ取り長い期間を一度に聞くと Amazon がエラーではなく「0件」を返すことがあります。月ごとに分けて聞いてください（AIにも警告が出ます）
2026年9月2日に追加した道具は参照系を一巡しました。上の表の権限エラー分と、変更する操作6本は未実測です。おかしな結果が出たら市倉さんへ。

変更する操作（実装済→管理者向け）

変更する操作は6本ありますが、通常業務で使うことはありません。価格・在庫・出荷確認は GoQ / RPA が行っています。管理者以外は触らないでください。 どれも同じ流れで動きます：1回目はプレビュー（送る内容の全体と確認コード）→ 内容を見て承認 → 確認コードを付けた2回目でだけ実行。 確認後に内容を変えると確認コードが合わなくなり、実行されません（見せた内容と違うものが送られるのを防ぐため）。

操作内容
update_listing
出品情報の一部更新		起きること　価格・数量・出品状態などが変わり、数分でお客様に見える
取り消し　プレビューに出る「変更前の値」を同じ形で戻す
安全装置　プレビュー時に Amazon 側の事前検証を通し、問題（issues）があれば警告。変更前の値を保存して返す
confirm_shipment
出荷確認（追跡番号登録）		起きること　注文が「出荷済み」になり、お客様に出荷メールが届く
取り消し　不可（Amazonサポート）
安全装置　FBA注文・出荷済み注文は拒否。注文に無い明細は止める。GoQ/RPAとの二重登録に注意
request_review
レビュー依頼の送信		起きること　Amazon からお客様へ「レビューのお願い」メールが届く
取り消し　不可。1注文1回だけ
安全装置　送れる状態か（配達後5〜30日等）を Amazon に先に確認し、送れなければ実行しない
submit_feed
フィードの送信		起きること　内容次第で価格・在庫・出品が一括で変わる
取り消し　処理開始前なら cancel_feed
安全装置　JSONの妥当性・件数・本文の先頭とハッシュをプレビュー。RPAと同じ対象を二重に更新しない
cancel_feed
フィードの取り消し		起きること　待ち行列のフィードが処理されなくなる
取り消し　送り直す
安全装置　待ち行列（IN_QUEUE）以外は送らず「取り消せない」と返す
cancel_analytics_query
集計の取り消し		起きること　実行中の Data Kiosk 集計が止まる
取り消し　もう一度実行する
安全装置　実行中以外は送らない
⚠️ 送信の途中で通信エラーになった場合は「送信したが受理されたか分からない」と表示されます。このときは再送せず、get_listing・get_order・list_feeds かセラーセントラルで結果を確認してください。確認せずに再実行すると二重更新・二重送信になります。

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「次に何をすればいいか」まで書いてあります
  • 招待コードの再発行、「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ
