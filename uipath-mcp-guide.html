UiPath MCP 利用ガイド

Claude のチャットから、社内RPA（UiPath Orchestrator）の実行状況・失敗の原因・ロボットの稼働状態を調べたり、ジョブの実行・再実行などの操作ができる社内コネクタです。「RPAが動いてない気がする」のような聞き方で大丈夫です。

注意事項

  • これは正規のUiPathコネクタではありません。生成AIで作成した電池屋用のコネクタです。正規のコネクタではないので、不具合が入っている可能性があります。おかしな動きに気づいたら、そのまま使い続けずに市倉さんへ知らせてください
  • このコネクタは動いている業務のRPAを直接操作できます（ジョブの実行・停止・再実行、トリガーの有効/無効など）。停止や再実行は出荷・発注などの業務処理に直結するため、変更する操作は最大限気を付けてください
  • RPAのログには注文番号などの業務データが含まれることがあります。回答や画面の内容を社外へ共有しないでください

はじめる（初回だけ・3分）

  1. 招待コードを手に入れる。Chatwork で コダック（RPA用アカウント）とのダイレクトチャットを開き、To を付けて「招待コードをください」と送ると、数秒で自分専用のコード（INV-あなたの名前-…）が返ってきます。全コネクタ共通・30日有効。すでに持っていればこの手順は不要です
  2. Claude の「設定 → コネクタ」を開き、一覧の 電池屋用-UiPathMCP をオンにする
  3. 初めて使うときに認可画面が開くので、招待コードを貼り付けて「接続を許可する」を押す。以後、コードの入力は二度と不要です
このコネクタを使えるのは 管理者（市倉・青木・池田） です。役割に含まれない人は、正しい招待コードを入れても「このコネクタの利用権限がありません」と表示されます。自分の役割が分からないとき・権限の相談は市倉さんへ。

分野こんなふうに聞く
稼働状況 今RPAは何が動いてる？／今日失敗したジョブはある？／ロボットはちゃんとつながってる？
失敗の調査 発注書作成のジョブ、なんで落ちたの？（実行ログから例外の内容まで読めます）／最近のエラーログを見せて

ツール一覧（24本）

AIが裏で使っている道具の一覧です。書＝変更する操作（8本）。変更する操作はすべて確認画面が先に出て、承認した2回目でだけ実行されます。

できないこと

やりたいことできる？理由・代わりの方法
RPAプロセスの中身を直す・新しく作る✕UiPath Studio の領域です。動かす・止める・設定値を変えるところまでがこのコネクタ
スケジュール（トリガー）の新規作成・削除✕影響が大きいため対象外。有効／無効の切り替えだけできます
ロボット・マシン・フォルダの追加・削除✕Orchestrator の画面で行ってください
パッケージのアップロード・デプロイ✕Studio からの公開手順で行ってください
アセットの中の資格情報（パスワード）を読む△ユーザー名までは見えますが、パスワードは UiPath 側が返しません（API仕様）

まだできないこと（UiPath側の制約）

機能使えない理由
資格情報アセットの更新結果の確認更新後にパスワードを読み戻せないため、ユーザー名の一致だけ確認しています
ログの全文検索Orchestrator の API はジョブ単位の取得のみ。期間や語での横断検索はできません

変更する操作（実装済→管理者向け）

変更する操作は8本あり、すべて業務処理（出荷・発注・受注取込）に直結します。管理者以外は触らないでください。 どれも同じ流れで動きます：1回目はプレビュー（対象と内容）→ 内容を見て承認 → 確認コードを付けた2回目でだけ実行。実行した記録（誰が・いつ・何を）はすべて残ります。

操作内容
start_job / restart_job
実行・再実行		起きること　RPAがその場で動き始める
取り消し　stop_job で停止（処理途中のデータは残る）
安全装置　プロセス名・ロボット・引数をプレビュー。再実行は二重処理にならないかを先に確認
stop_job
停止		起きること　実行中の処理が途中で止まる
取り消し　start_job でやり直し
安全装置　対象ジョブの状態をプレビュー。出荷・発注中は担当者に確認してから
resume_job
再開		起きること　保留中のジョブが続きから動く
取り消し　stop_job
安全装置　保留状態でなければ送らない
set_trigger_enabled
スケジュールの有効／無効		起きること　定期実行が止まる／再開する
取り消し　逆に切り替える
安全装置　現在の状態をプレビュー。無効にしたまま忘れないこと
set_asset
アセット更新		起きること　RPAが次回から新しい値で動く
取り消し　前の値に戻す（プレビューに現在値を出す）
安全装置　種別（Text/Integer/Bool/Credential）を既存アセットから自動判定。資格情報は全置換のためパスワードを毎回入力（読み戻せない）。Secret型は対象外
add_queue_item / retry_queue_item
キュー投入・再試行		起きること　RPAがそのアイテムを処理する
取り消し　処理前なら Orchestrator で削除
安全装置　内容をプレビュー。重複投入に注意
⚠️ 送信の途中で通信エラーになった場合は「送信したが受理されたか分からない」と表示されます。このときは再実行せず、list_jobs か Orchestrator の画面で状態を確認してください。確認せずに再実行すると二重処理になります。

困ったとき

  • エラーが出たら、まずエラー文を読んでください。「次に何をすればいいか」まで書いてあります
  • 招待コードはコダックへ To 付きで「招待コードをください」（期限切れも同じ）。権限の相談、「こういうことも聞けるようにしてほしい」という要望 → 市倉さん（システム担当）へ。要望は「どの業務で・何を知りたい／したいか」を添えてもらえると早く作れます
